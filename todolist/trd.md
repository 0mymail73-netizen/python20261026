# TODO List 기술 요구사항 문서 (TRD)

## 1. 기술 구성

- **HTML5**: 문서 구조와 의미 있는 폼, 버튼, 목록 요소
- **CSS3**: 레이아웃, 상태별 스타일, 반응형 디자인, 포커스 표시
- **JavaScript (ES6+)**: 목록 상태, 사용자 이벤트, 렌더링, 브라우저 저장소 연동
- **저장소**: 브라우저 `localStorage`
- 프레임워크, 빌드 도구, 서버, 외부 런타임 의존성은 사용하지 않는다.

## 2. 권장 파일 구성

```text
todolist/
├── index.html
├── style.css
└── script.js
```

문서 파일(`prd.md`, `trd.md`, `task.md`)은 프로젝트 계획을 위해 루트에 유지한다. 실제 구현 시 위 세 파일을 추가한다.

## 3. 데이터 모델

할 일 한 건은 다음 필드를 가진다.

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | 문자열 | 항목을 구분하는 고유 식별자 |
| `text` | 문자열 | 할 일 내용. 저장 전 앞뒤 공백 제거 |
| `completed` | 불리언 | 완료 여부 |
| `createdAt` | 숫자 또는 ISO 문자열 | 생성 시각 |

저장 키는 `todolist.tasks`로 한다. 저장 값은 할 일 객체 배열을 JSON으로 직렬화한 값이다. 필수 필드와 타입을 검증한 뒤 상태에 반영한다. 파싱이나 형식 검증에 실패하면 오류를 명확히 기록하고 안전하게 빈 목록으로 초기화한다.

## 4. 동작 구조

1. `index.html`에서 스타일시트와 스크립트를 연결한다.
2. `script.js` 시작 시 저장된 데이터를 읽고 형식을 확인한다.
3. 현재 목록과 필터를 기준으로 화면을 렌더링한다.
4. 사용자 동작은 목록 상태를 갱신한 후 저장하고 화면을 다시 렌더링한다.
5. 목록 내용과 표시 개수는 동일한 상태에서 계산해 서로 불일치하지 않게 한다.

### 상태 및 이벤트

- 할 일 추가: 입력값 정리 및 검증 → 새 항목 생성 → 저장 → 렌더링
- 완료 전환/수정/삭제: 대상 ID를 기준으로 변경 → 저장 → 렌더링
- 필터 변경: 표시 필터만 변경 → 렌더링
- 완료 항목 전체 삭제: 완료 항목 제거 → 저장 → 렌더링
- 키보드 입력: 입력 후 Enter로 추가하고, 편집 모드에서는 Enter로 저장 및 Escape로 취소

## 5. 화면 및 접근성

- 문서 언어를 한국어로 지정하고 적절한 제목 구조를 사용한다.
- 입력 폼을 사용해 Enter 제출을 지원하고 입력 요소에 레이블을 연결한다.
- 완료 상태를 체크박스 등 의미 있는 컨트롤로 표현한다.
- 아이콘만 있는 버튼은 접근 가능한 이름을 제공한다.
- 모든 인터랙티브 요소에 눈에 보이는 키보드 포커스 스타일을 둔다.
- 모바일 우선 또는 동등한 반응형 방식으로 좁은 화면을 지원한다.
- 색상만으로 완료 여부나 선택 필터를 구분하지 않는다.

## 6. 보안 및 오류 처리

- 사용자 할 일 텍스트는 `textContent` 등 텍스트 전용 DOM API로 출력하고 HTML 문자열로 삽입하지 않는다.
- `localStorage` 접근과 JSON 파싱의 실패를 구분해 처리하고 콘솔에 원인을 기록한다.
- 저장소 접근이 불가능한 환경에서는 오류를 숨기지 않고 사용자에게 저장이 제한됨을 안내한다. 저장 실패가 앱 동작을 성공한 것처럼 보이게 해서는 안 된다.
- 사용자 입력은 비어 있지 않은지 검증한다. 별도 길이 제한을 도입할 경우 UI와 검증 로직에서 동일한 기준을 적용한다.

## 7. 테스트 및 검증 계획

- 추가: 정상 텍스트, 공백만 입력, Enter 제출
- 수정: 저장, 취소, 빈 문자열 처리
- 상태: 완료/미완료 전환, 각 필터의 표시 결과, 남은 항목 개수
- 삭제: 개별 삭제 및 완료 항목 전체 삭제
- 지속성: 저장 후 새로고침 시 복원
- 예외: 저장 데이터 누락/손상, 저장소 접근 실패
- 사용성: 키보드 조작, 좁은 화면 레이아웃, 포커스 표시
- 브라우저 개발자 도구에서 콘솔 오류와 네트워크 외부 의존성 여부 확인

## 8. 실행 방법

구현 후 `index.html`을 최신 브라우저에서 직접 열어 실행한다. 서버 측 기능이 없으므로 별도 서버는 필요하지 않다. 브라우저 정책에 따라 로컬 파일에서 저장소 동작이 제한되는 경우 로컬 정적 파일 서버로 확인한다.
